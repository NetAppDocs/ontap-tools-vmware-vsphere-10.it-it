= Distribuisci ONTAP tools
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Distribuisci ONTAP tools for VMware vSphere come appliance a nodo singolo extra-small che supporta i datastore NFS e VMFS. Il processo di distribuzione richiede fino a 45 minuti.

.Prima di iniziare
Se implementi una configurazione a nodo singolo extra-small, un archivio di contenuti è facoltativo. Per le implementazioni multi-nodo o HA, un archivio di contenuti è obbligatorio.

In VMware, un archivio di contenuti archivia modelli di macchine virtuali, vApp template e altri file. Usare un archivio di contenuti semplifica la distribuzione perché non dipende dall'accesso diretto alla rete durante le operazioni sui template.

Prima di creare un archivio di contenuti:

* Creare la libreria dei contenuti su un datastore condiviso in modo che tutti gli host del cluster possano accedervi.
* Crea l'archivio di contenuti prima di distribuire ONTAP tools for VMware vSphere OVA.
* Conserva il modello OVA nell'archivio di contenuti dopo la distribuzione.



NOTE: Se prevedi di abilitare l'HA in un secondo momento, distribuisci la VM ONTAP tools in un cluster ESXi o pool di risorse, non direttamente su un host ESXi.

Per creare un archivio di contenuti:

. Scarica i file binari ONTAP tools for VMware vSphere (_.ova_) e i certificati firmati da  https://mysupport.netapp.com/site/products/all/details/otv10/downloads-tab["Sito di supporto NetApp"^].
. Accedi al vSphere Client.
. Dal menu vSphere Client, seleziona *Librerie di contenuti*.
. Seleziona *Crea*.
. Inserisci un nome e crea l'archivio di contenuti.
. Apri l'archivio di contenuti che hai creato.
. Seleziona *Azioni* > *Importa elemento* e importa il file OVA.



NOTE: Per ulteriori informazioni, vedi  https://blogs.vmware.com/vsphere/2020/01/creating-and-using-content-library.html["Creazione e utilizzo della libreria di contenuti"].


NOTE: Prima della distribuzione, imposta il cluster Distributed Resource Scheduler (DRS) su "Conservative" per impedire la migrazione delle VM durante l'installazione.

ONTAP tools per VMware vSphere viene inizialmente distribuito in una configurazione non HA. A partire da ONTAP tools 10.6, l'aggiunta a caldo della CPU e la connessione a caldo della memoria sono abilitate per impostazione predefinita. Per passare a una configurazione HA in seguito, queste funzionalità devono essere abilitate.

.Fasi
. Scarica il file OVA degli ONTAP tools e i certificati firmati da  https://mysupport.netapp.com/site/products/all/details/otv10/downloads-tab["Sito di supporto NetApp"^]. Se hai già importato l'OVA nel tuo archivio di contenuti, salta questo passaggio.
. Accedere al server vSphere.
. Vai al pool di risorse, cluster o host dove vuoi distribuire l'OVA.
+

IMPORTANT: Non archiviare la macchina virtuale degli ONTAP tools sui datastore vVols che gestisce.

. Distribuisci il file OVA dall'archivio di contenuti o dal sistema locale.
+
|===


| Dal sistema locale | Dalla libreria di contenuti 


| a. fare clic con il pulsante destro del mouse e selezionare *Deploy OVF template...*. b. scegliere il file OVA dall'URL o navigare fino alla posizione desiderata, quindi selezionare *Next*. | a. accedere alla libreria di contenuti e selezionare l'elemento della libreria che si desidera distribuire. b. selezionare *azioni* > *Nuova VM da questo modello* 
|===
. In *Seleziona un nome e una cartella*, inserisci il nome e la posizione della VM.
. Selezionare una risorsa di computer e selezionare *Avanti*. Se lo si desidera, selezionare la casella *Accendi automaticamente VM distribuita*.
. Esaminare i dettagli del modello e selezionare *Avanti*.
. Leggere e accettare il contratto di licenza e selezionare *Avanti*.
. Selezionare lo spazio di archiviazione per la configurazione e il formato del disco, quindi selezionare *Avanti*.
. Selezionare la rete di destinazione per ciascuna rete di origine e selezionare *Avanti*.
. Nella finestra *Personalizza modello*, inserisci i valori richiesti. image:../media/custom-temp-p2.png["Personalizza il modello"]
+
[IMPORTANT]
====
I valori presenti nella pagina *Personalizza modello* sono necessari per una distribuzione riuscita.

Presta particolare attenzione a questi campi:

** *Nome host*: Inserisci l'host name della VM ONTAP tools. Usa un formato di host name valido.
** *Indirizzo IP degli ONTAP tools*: Questa è l'interfaccia di gestione principale utilizzata per accedere agli ONTAP tools.
** *Indirizzo IPv4*: Questo è l'indirizzo IP del nodo utilizzato per la shell diagnostica e l'accesso SSH per la risoluzione dei problemi e la manutenzione.


Se usi nomi DNS per l'host o vCenter, assicurati che quei nomi vengano risolti correttamente nel DNS.

====
+

NOTE: Il nome host vCenter è il nome dell'istanza di vCenter Server in cui è distribuito l'appliance degli strumenti ONTAP .

+
Se stai distribuendo ONTAP tools in una topologia a due vCenter Server, dove l'appliance è ospitata in un'istanza vCenter e ne gestisce un'altra, assegna un ruolo con restrizioni all'istanza vCenter che ospita ONTAP tools. Crea un utente e un ruolo vCenter dedicati con solo le autorizzazioni necessarie per la distribuzione del template OVF. Per dettagli, vedi link:../concepts/rbac-vcenter-use.html#vsphere-object-hierarchy["Ruoli inclusi nei tool ONTAP per VMware vSphere 10"].

+
Per l'istanza vCenter gestita da ONTAP tools, assicurati che l'account utente vCenter abbia i privilegi di amministratore.

+
** I nomi host devono includere lettere (A-Z, a-z), cifre (0-9) e trattini (-). Per il dual stack, specifica l'host name mappato all'indirizzo IPv6.
+

NOTE: IPv6 puro non è supportato. La modalità mista è supportata con una VLAN che contiene sia indirizzi IPv6 che IPv4.

** L'indirizzo IP di ONTAP tools (in precedenza load balancer) è l'endpoint esterno per ONTAP tools Manager (`\https://<ip>:8443/virtualization/ui/`, le chiamate API e l'accesso ai plug-in dall'interfaccia utente di vCenter.
** L'indirizzo IP virtuale di ONTAP tools (precedentemente denominato node interconnect) viene assegnato al server API di Kubernetes (kube-api) e funge da IP virtuale per il control plane di Kubernetes.
** L'indirizzo IPv4 è l'indirizzo di gestione del nodo mappato all'host name specificato e viene utilizzato per la shell diagnostica e l'accesso SSH.


. Rivedere i dettagli nella finestra *Pronto per il completamento*, selezionare *fine*.
+
Quando l'attività di distribuzione ha inizio, l'avanzamento viene visualizzato nella barra delle attività di vSphere.

. Se non hai selezionato l'accensione automatica, accendi la VM al termine dell'attività.


Monitora lo stato di avanzamento dell'installazione dalla console web della macchina virtuale.

Se nel modulo OVF sono presenti delle discrepanze, viene visualizzata una finestra di dialogo che richiede di intraprendere azioni correttive. Usa il tasto Tab per navigare, apporta le modifiche necessarie e seleziona *OK*. Hai tre tentativi per risolvere i problemi. Se i problemi continuano dopo tre tentativi, l'installazione si interrompe e dovresti riprovare l'installazione su una nuova macchina virtuale.
